Lesson 3: Streaming Responses for Better UX

Mission Connection: Streaming responses will make your educational chatbot feel more responsive and natural, like a real conversation.

What You'll Learn

  • Why streaming is important for chat applications
  • How to implement streaming with Spring AI
  • Handling streaming responses in REST controllers
  • Comparing synchronous vs streaming responses

Why Streaming Matters

Without streaming, users have to wait for the entire response before seeing anything. This feels slow and unnatural.

Streaming Benefits:
  • Faster perceived response - Users see output immediately
  • Better UX - Feels like real-time conversation
  • Progressive loading - Long responses appear gradually
  • Interruptible - Users can stop generation early

Step 1: Understanding Streaming in Spring AI

Spring AI provides two ways to stream responses:

  • Flux<String> - Streams text chunks
  • Flux<ChatResponse> - Streams full response objects

The StreamingChatModel interface provides the stream() method that returns a reactive Flux.

Step 2: Update Your Chat Service

Add streaming methods to your ChatService.java:

package br.com.felipegardin.chat.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;
import lombok.RequiredArgsConstructor;

@Service
@RequiredArgsConstructor
public class ChatService {

    private final ChatClient simpleChatClient;
    private final ChatClient chatClientWithMemory;

    public String simpleChat(String input) {
        return this.simpleChatClient.prompt()
                .user(input)
                .call()
                .content();
    }

    public String chatWithMemory(String input, String conversationId) {
        if (conversationId == null || conversationId.isBlank()) {
            return simpleChat(input);
        }
        return chatClientWithMemory.prompt()
                .user(input)
                .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
                .call()
                .content();
    }

    // Streaming methods
    public Flux<String> simpleChatStream(String input) {
        return this.simpleChatClient.prompt()
                .user(input)
                .stream()
                .content();
    }

    public Flux<String> chatWithMemoryStream(String input, String conversationId) {
        if (conversationId == null || conversationId.isBlank()) {
            return simpleChatStream(input);
        }
        return chatClientWithMemory.prompt()
                .user(input)
                .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
                .stream()
                .content();
    }
}

Step 3: Update Your Controller

Add streaming endpoints to your ChatController.java:

package br.com.felipegardin.chat.controller;

import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.ResponseBody;
import reactor.core.publisher.Flux;

import br.com.felipegardin.chat.service.ChatService;
import lombok.RequiredArgsConstructor;

@RestController
@RequestMapping("/chat")
@RequiredArgsConstructor
public class ChatController {

    private final ChatService chatService;

    @GetMapping("simple")
    public String simpleChat(@RequestParam String input) {
        return chatService.simpleChat(input);
    }

    @GetMapping("with-memory")
    public String chatWithMemory(@RequestParam String input, @RequestParam(required = false) String conversationId) {
        return chatService.chatWithMemory(input, conversationId);   
    }

    // Streaming endpoints
    @GetMapping(value = "simple/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    @ResponseBody
    public Flux<String> simpleChatStream(@RequestParam String input) {
        return chatService.simpleChatStream(input);
    }

    @GetMapping(value = "with-memory/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    @ResponseBody
    public Flux<String> chatWithMemoryStream(
            @RequestParam String input, 
            @RequestParam(required = false) String conversationId) {
        return chatService.chatWithMemoryStream(input, conversationId);
    }
}

Step 4: Test Streaming

Test the streaming endpoints:

  1. Simple streaming: 
    curl -N "http://localhost:8080/chat/simple/stream?input=Tell+me+a+joke"
  2. Streaming with memory: 
    curl -N "http://localhost:8080/chat/with-memory/stream?input=My+name+is+Alex&conversationId=student1"
  3. Follow-up (same conversation): 
    curl -N "http://localhost:8080/chat/with-memory/stream?input=What+is+my+name?&conversationId=student1"
Note: The -N flag in curl disables buffering, so you can see the streaming output in real-time.

Understanding the Code

Key Concepts:
  • .stream().content() - Returns Flux<String> instead of String
  • MediaType.TEXT_EVENT_STREAM_VALUE - Sets correct content type for streaming
  • Flux<String> - Reactive type that emits multiple strings over time
  • @ResponseBody - Required for returning reactive types

Synchronous vs Streaming Comparison

Feature Synchronous Streaming
Response Type String Flux<String>
Wait Time Until complete Immediate first chunk
Memory Usage Stores full response Processes chunks
User Experience Delayed Real-time
Use Case Short responses Long responses, chat
